# 삼다방 프론트엔드

Next.js App Router와 TypeScript로 구성한 프론트엔드 기본 구조다. 화면 범위, 라우트-컨트롤러 매핑, 개발 규칙, 진행 현황은 [프론트엔드 개발 문서](../docs/FRONTEND.md)를 따른다.

## 로컬 실행

```bash
cd frontend
npm install
cp .env.local.example .env.local
# .env.local의 API_ORIGIN을 실행 중인 Spring 백엔드 주소로 설정
npm run dev
```

## 세션 인증

회원가입·로그인·로그아웃·본인 정보 조회는 Spring 백엔드와 연결했다. 백엔드도 실행해야 하며 로컬에서는 프론트·백엔드 호스트를 `localhost`로 통일한다. `API_ORIGIN`은 서버 전용 설정이며 브라우저에 공개하지 않는다.

- 가입 후 별도로 로그인해 기존 자동 로그인 흐름을 유지한다. 가입만 성공하고 로그인에 실패하면 가입 완료 안내와 로그인 화면으로 이동한다.
- Server Action이 백엔드 CSRF를 받고 세션 쿠키를 전달한다. 세션 ID 변경·만료를 포함한 모든 Set-Cookie를 응답에 반영하며 속성을 유지한다.
- SSR은 브라우저 JSESSIONID를 명시해 `GET /api/v1/my`를 no-store로 조회한다. 보호 경로는 Proxy와 서버 권한 검사로 확인한다.
- 목 인증 쿠키와 목 기본 계정은 인증에 사용하지 않는다. 관리자는 기존 백엔드 초기 설정 절차를 따른다.
- `next.config.ts`는 `/api/v1/*`만 백엔드로 중계한다. 기존 `/api/music-box/version`, `/api/story-speech`는 유지한다.

인증 외 메뉴·주문·뮤직박스·관리자 회원 화면은 아직 목 저장소를 사용한다. 해당 목 기능은 운영 환경에서 차단되며, 각 기능의 백엔드 연결은 별도 작업이다. 현재 브라우저 인증 검증은 로컬 개발 서버와 격리 DB를 기준으로 한다.

인증 구현·환경·검증은 [6단계 기록](../backend/docs/2026-10-25-auth-step6.md), 브라우저 재현 방법은 [E2E 안내](e2e/README.md)에 정리한다.

## 뮤직박스

`/music-box`에서 방문자가 이름, 신청곡, 가수, 사연을 남기면 `.data/music-requests.json`에 접수된다. `/admin/music-box`에서 관리자가 사연을 확인하고 재생 가능한 HTTPS 음원 주소를 입력하거나 MP3·M4A·OGG·WAV 파일(최대 25MB)을 올려 선곡한다. 로컬 업로드는 Git에서 제외된 `public/audio/`에 저장한다. 고객 화면과 관리자 화면의 오디오 플레이어에서 재생 버튼을 누르면 해당 음원을 들을 수 있다. 곡이 끝나면 관리자가 `재생 완료로 표시`를 누른다. 브라우저의 자동 재생 제한 때문에 다른 방문자의 재생이 자동으로 시작되거나 서로 동기화되지는 않는다. 음원 사용 권한과 실제 서비스용 저장소는 배포 전에 별도로 준비해야 한다.

## 프론트엔드 메뉴 계약

관리자 메뉴 화면은 프론트엔드 모델을 기준으로 먼저 구현한다. 메뉴 필드는 `id`, `name`(한글), `nameEn`(영어), `imageUrl`, `description`, `category`, `price`, `available`, `isNew`, `recommended`, `createdAt`, `updatedAt`이다. 목록 맨 왼쪽에 이미지를 표시한다. 검색 영역에서 한글·영문 메뉴명, 카테고리·상태 필터와 정렬을 선택한 뒤 검색 버튼으로 함께 적용한다. 등록일은 목록에 표시하고 정렬에 사용할 수 있다. 등록·수정 폼에서 메뉴명, 이미지 주소, 설명, 가격, 판매 상태, NEW·추천 여부를 입력하고, 카테고리는 목업 목록(커피·차·쥬스·다과·세트)에서 선택한다. 이미지 주소를 비우면 기본 이미지가 사용된다.

현재 관리자 화면은 `app/_lib/mock/menus.ts`를 통해 `.data/menus.json`에 등록·수정·삭제 결과를 저장한다. 백엔드 API는 이 화면 계약에 맞춰 추후 연결한다. `.data/`는 Git에서 제외한다.

## 관리자 회원 관리

관리자 계정으로 로그인한 뒤 `/admin/users`에서 이름·이메일 검색, 이용 상태·권한 필터, 정렬, 페이지 이동을 이용할 수 있다. 회원 이름이나 상세 보기로 `/admin/users/[id]`에 진입하며 검색 조건은 목록으로 돌아갈 때 유지된다. 목록과 상세에서 이용 정지·해제를 확인 후 처리한다. 관리자 계정은 상태 변경 대상에서 제외한다.

이 관리 화면의 목록·상태 변경은 아직 목 회원 저장소(`.data/users.json`)를 사용하며, 새 백엔드 가입 계정과는 별개다. 이 화면에서 목 회원을 정지해도 실제 백엔드 계정 상태를 변경하지 않는다. 관리자 권한은 실제 세션으로 확인하고, 회원 관리 GET·PUT API 연결은 별도로 진행한다.
